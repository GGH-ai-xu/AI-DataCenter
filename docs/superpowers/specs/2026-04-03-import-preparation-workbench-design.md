# Import Preparation Workbench UI Redesign

## Goal

把 `/import` 从“单页纵向堆叠的导入表单”重构成“进入控制台前的准备工作台”。页面需要在高信息密度下保持清晰层级、稳定布局和强流程感，同时继续遵守“控制台只治理本次导入选中的卡”这一边界。

## Scope

本次设计只覆盖前端准备页 UI 和其直接结构边界：

- `frontend/src/views/ImportWorkspace.vue`
- `frontend/src/components/import/*`
- 与准备页结构强相关的前端结构测试

不改导入层后端协议，不改控制台页面功能边界，不新增新的导入业务语义。

## Problems To Solve

1. 当前 `/import` 虽然已经是独立页面，但右侧主内容仍以单列连续堆叠为主，视觉上像“大表单”而不是“准备工作台”。
2. `导入来源 / 扫描摘要 / GPU 选择 / 提交动作` 被顺序平铺，分类感不足，信息密度一高就显得拥挤。
3. 页面缺少稳定的左右职责边界，后续继续加信息时容易再次出现“一处变高，整页跟着乱”的联动。
4. 连接配置、验机信息、选卡范围是三个不同阶段，但当前没有明确的阶段切换结构。

## Confirmed Decisions

### Page Skeleton

- 桌面端采用 `左侧固定摘要栏 + 右侧主工作台` 双栏结构。
- 移动端折叠为单列，左侧摘要栏上移到顶部，右侧工作台保持阶段切换。
- 页面语义是“启动控制台前的准备工作台”，不是普通登录页，也不是单纯的配置表单。

### Left Sidebar

左侧固定摘要栏只承载准备态聚合信息，不直接混入右侧阶段内容：

- 品牌与页面标题
- 当前连接摘要，例如 `SSH Linux / 10.0.0.8 / 已扫描`
- 本次选择摘要，例如 `已选 4 张 GPU`
- 当前有效导入范围说明，例如 `控制台只治理本次选中的卡`
- 流程提示，例如“完成扫描后勾选 GPU，再进入控制台”

左栏允许换行，但宽度保持稳定，不随右侧内容高度变化。

### Right Workbench

右侧主工作台固定分成三层：

1. 顶部 `主 Tab 头`
2. 中部 `阶段内容区`
3. 底部 `提交动作区`

这三层必须结构隔离。只有阶段内容区滚动，顶部 tab 头和底部提交动作区保持稳定。

## Stage Tabs

### 1. 连接来源

该阶段只负责建立目标连接并发起扫描，不预先承载硬件详情。

主舞台分成三块：

- `来源模式带`：本机 Agent / 远程 Agent / SSH Linux
- `连接表单卡`：公共字段与 SSH 专属字段分层展示
- `扫描动作卡`：扫描按钮、反馈状态、最近一次扫描状态

辅侧信息带只放连接相关摘要：

- 当前目标标签
- 当前认证方式
- 当前扫描地址
- 错误或警告摘要

### 2. 硬件概览

该阶段只负责确认扫描结果是否可信，不再承担连接编辑。

主舞台分成两层：

- `主机概览条`：CPU 占用、线程数、内存总量、运行时状态、sudo 能力
- `GPU 总览区`：展示本次扫描出的 GPU 池，但以只读验机为主

GPU 总览区提供轻量二级切换：

- `卡片视图`
- `摘要视图`

辅侧信息带只放：

- 目标地址或 SSH 指纹
- 扫描来源
- 扫描是否成功
- 本次发现 GPU 数量

### 3. 选卡导入

该阶段只负责确定控制台治理范围。

主舞台分成两块：

- `选择工具条`：已选数量、全选、清空、简单筛选
- `候选卡池`：GPU 卡片网格，只负责勾选和取消勾选

候选卡池提供轻量二级切换：

- `全部候选`
- `已选清单`

辅侧信息带只放：

- 当前导入范围摘要
- 控制台生效说明
- 导入前校验提示

底部独立动作区只保留：

- `导入并进入控制台`
- 一条状态说明

该动作区不和 GPU 卡池滚动绑定。

## Layout And Coupling Rules

### Layout Stability

- 左侧摘要栏宽度固定在稳定区间内，不因为右侧阶段内容变化而改变。
- 右侧工作台使用固定骨架：`auto minmax(0, 1fr) auto`。
- 不使用绝对定位、负 margin 或内容高度耦合来“挤”出布局。

### Scroll Rules

- 页面不引入多层混乱滚动。
- 右侧只有阶段内容区负责主滚动。
- GPU 候选卡池在项目很多时优先自滚动，而不是把整页无限拉长。

### Text Rules

- 标题、说明、状态、标签统一允许换行。
- 禁止用 `text-overflow: ellipsis` 隐藏信息。
- 长地址、指纹、SSH 文本必须使用 `word-break` 或分段容器。
- GPU 卡片的指标区使用固定网格，避免因名称过长破坏其他指标布局。

### Density Rules

- 信息密度通过分类、分层和统一间距实现，而不是靠压缩字体。
- 区块间距、卡片间距、卡片内部字段间距必须分级一致。
- 主操作区和普通信息区必须有清晰视觉分层，避免形成“满屏小卡片”。

### Decoupling Rules

- 连接阶段的反馈只能影响连接阶段自身状态卡。
- GPU 选择数量变化只更新左侧摘要与选卡阶段，不推挤其他阶段布局。
- 左侧摘要栏只消费聚合后的准备态数据，不依赖右侧具体组件的内部排版。
- 底部提交动作区只依赖导入前校验状态，不依赖当前 tab 内容高度。

## Component Boundaries

### Page Shell

- `ImportWorkspace.vue`
  - 只负责状态、数据获取、tab 状态、导入提交
- `ImportPrepSidebar.vue`
  - 只负责左侧固定摘要栏
- `ImportPrepWorkbench.vue`
  - 只负责右侧主工作台骨架
- `ImportPrepTabs.vue`
  - 只负责顶层阶段切换

### Stage Components

- `ImportConnectionStage.vue`
  - 组合 `ImportSourcePanel.vue`，补连接侧信息和扫描状态区
- `ImportHardwareStage.vue`
  - 组合 `ImportHardwareSummary.vue`，补 GPU 只读验机区
- `ImportSelectionStage.vue`
  - 组合 `ImportGpuGrid.vue`，补二级切换和选择工具条

### Existing Components

- `ImportSourcePanel.vue`
  - 保留表单职责
- `ImportHardwareSummary.vue`
  - 保留主机与运行时摘要职责
- `ImportGpuGrid.vue`
  - 保留卡片网格与选中逻辑

这些组件不再直接决定整页层级结构。

## Verification Targets

需要新增或更新前端结构测试，至少覆盖：

1. `/import` 存在 `左侧摘要栏 + 右侧工作台` 双栏骨架。
2. 页面存在 `连接来源 / 硬件概览 / 选卡导入` 三个主 tab。
3. 底部提交动作区独立存在，不和阶段内容混排。
4. `ImportSourcePanel / ImportHardwareSummary / ImportGpuGrid` 被重组进阶段组件，而不是继续在页面中直接平铺。
5. 准备页与阶段组件中不允许出现 `text-overflow: ellipsis`。
6. 工作台内容区和 GPU 卡池具有各自独立滚动容器。

## Non-Goals

- 不把准备页改成严格一步一步的向导流。
- 不在准备页里加入控制台内部治理动作。
- 不让左侧摘要栏承担硬件详情主视图。
- 不重新定义导入接口、导入上下文或控制台过滤语义。
