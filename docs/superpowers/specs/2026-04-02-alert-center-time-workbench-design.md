# 告警中心时间工作台设计

## 目标

重构 `frontend/src/views/AlertCenter.vue`，把当前“摘要 + 主表 + 右侧实时流”的单层布局改成时间语义明确的工作台，满足以下约束：

1. 不平铺堆砌，首屏有清晰主次和层级。
2. 按任务类型分类，不同类别信息放入不同 tab。
3. 不出现文字截断、组件重叠、无关区域联动位移。
4. 信息密度高但不拥挤，适合桌面工作台使用。

## 用户确认的方向

- 一级组织方式：按时间语义
- 默认首屏：`实时流`
- 实时流口径：仅展示未确认告警
- 今日告警簿：使用时间线账页
- 历史归档：按类型归档

## 范围

本轮仅重构告警中心相关前端结构与样式：

- `frontend/src/views/AlertCenter.vue`
- `frontend/src/components/alerts/AlertSummaryPanel.vue`
- `frontend/src/components/alerts/AlertHistoryTable.vue`
- 新增告警中心专用子组件
- 对应前端 UI 结构测试

## 非目标

- 不新增后端接口
- 不修改告警数据模型
- 不改全站导航结构
- 不调整告警业务语义，仅调整展示组织和交互层级

## 现状问题

### 1. 页面仍然只有单层主从结构

当前页面本质上仍然是“一个历史表 + 一个右侧实时流侧栏”，只是在表格上方加了一层摘要。实时处置、当日复盘、历史归档三类任务共享同一视图节奏，缺少明确分舱。

### 2. 历史记录仍主要依赖表格式网格

`AlertHistoryTable.vue` 虽然已经比原始表格更柔和，但核心仍是多列网格行。长告警文案、时间、状态和确认操作仍处在同一行栅格中，未来字段增减时容易重新出现挤压和联动问题。

### 3. 实时与历史互相占用注意力

实时告警被固定在侧栏，历史告警占据主区，但两者同时暴露在一页里。用户值守时会被历史表分散注意力，复盘时又会被实时流打断，任务流不清晰。

## 信息架构

告警中心改为三段式时间工作台：

### 1. 实时流

默认首屏，只展示未确认告警。目标是快速发现并处理当前风险。

- 顶部为紧凑摘要带，仅保留 `严重未确认`、`总未确认`、`最近 1 小时新增` 三个关键指标。
- 主区显示按时间段分组的未确认告警流，例如“刚刚”“近 5 分钟”“更早”。
- 右侧稳定副栏显示风险摘要、类型过滤和操作提示。

### 2. 今日告警簿

用于当天复盘，不再使用横向表格，而是使用垂直时间线账页表达告警演化。

- 每个时间节点为一张账页卡。
- 账页卡拆为两层：头部元信息、正文与动作区。
- 长文案允许换行，状态和操作区固定，不与文本争宽度。

### 3. 历史归档

用于长期追踪，按类型组织为 `温度`、`功率`、`显存`、`平台自检` 四类。

- 先展示类型摘要条。
- 当前选中类型的明细独立显示。
- 不同时展示全部类型的历史长列表。

## 页面结构

### 顶部层

- 使用 `WorkspaceSummary`
- 只保留页面标题和关键指标徽标组
- 不保留额外描述性大段文案

### Tab 层

- 使用 `WorkspaceTabs`
- tab 固定为 `实时流 / 今日告警簿 / 历史归档`
- 默认 `activeTab = 'realtime'`

### 内容层

- `实时流` 使用主副双栏
- `今日告警簿` 使用单列时间线账页
- `历史归档` 使用“类型摘要条 + 当前类型归档明细”上下结构

三类布局彼此独立，切换某个 tab 的内容不牵动其他 tab 的布局。

## 组件拆分

### 保留并瘦身

- `AlertSummaryPanel.vue`
  - 从三张普通摘要卡，改为紧凑摘要带
  - 只承载关键数字，不承载长说明

### 新增组件

- `AlertRealtimeStream.vue`
  - 负责未确认实时流主区
- `AlertRealtimeSidebar.vue`
  - 负责实时流副栏，包括类型过滤与风险摘要
- `AlertDaybookTimeline.vue`
  - 负责今日时间线账页
- `AlertArchiveBoard.vue`
  - 负责历史归档页
- `AlertArchiveTypeTabs.vue`
  - 负责归档类型切换

### 降级或替换旧组件

- `AlertHistoryTable.vue`
  - 不再作为告警中心整页主结构
  - 如需保留，仅可作为归档页的局部明细视图

## 布局规则

### 1. 不用硬编码列网格承载整页主结构

主页面不再依赖多列表头或固定列网格来组织核心信息，避免文案增长后引起整行挤压。

### 2. 长文本自然换行

告警文案、说明、时间节点描述统一允许换行，不使用 `nowrap`、省略号或隐藏裁切承载核心信息。

### 3. 主区与副区职责分离

实时流页签中：

- 主区只负责告警流本身
- 副区只负责筛选、摘要、提示

两区分别堆叠，互不联动。

### 4. 密度靠分组，不靠堆叠

高密度通过时间分段、类型摘要、统一卡片节奏实现，而不是靠继续增加卡片数量或缩小间距。

## 交互规则

### 实时流

- 默认只显示未确认告警
- 支持类型筛选和刷新
- 不再暴露重复的“仅显示未确认”切换

### 今日告警簿

- 默认展示今日全部记录
- 支持在时间线节点内执行确认动作
- 状态变化仅更新当前节点内容，不影响整体布局

### 历史归档

- 默认进入第一个类型
- 切换类型只影响归档区内容
- 不影响实时流和今日告警簿的滚动状态与布局

## 测试与验收

需要补充前端结构测试，至少覆盖以下约束：

1. `AlertCenter.vue` 存在 `activeTab`
2. `AlertCenter.vue` 使用 `WorkspaceTabs`
3. 默认 tab 为 `realtime`
4. 存在 `today` 与 `archive` 页签结构
5. `AlertHistoryTable` 不再作为唯一主结构
6. 告警中心主视图不再依赖全页多列表头栅格
7. 视图中不出现文字裁切相关样式

页面完成后应满足：

1. 值守用户首屏只看到待处理实时告警，而不是被历史列表分散注意力。
2. 当日告警复盘可以沿时间线阅读，不依赖横向表格扫描。
3. 历史归档按类型进入，不出现所有历史记录一次性堆满。
4. 文本、卡片和操作区不会出现截断、重叠或无关联动位移。
