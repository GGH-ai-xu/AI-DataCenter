# 2026-04-09 AI 助手悬浮窗工作台布局设计

## 背景

`frontend/src/views/AIAssistant.vue` 在完成“统一聊天工作台 + 模型配置”两页收口后，信息架构已经比旧版清晰，但页面主轴仍然存在明显问题：

1. 页面中部仍保留了一层 `工作台 / 模型配置` 页签，占用了首屏最有价值的垂直空间。
2. 聊天区被页签、留白和松散的外围结构继续压缩，输入框与消息流不够突出。
3. 左侧会话区当前表现更像一块空白容器，缺少明确标题和空状态说明，首次进入时几乎看不出这是“会话栏”。
4. 模型配置虽然已从旧三页结构收口，但它仍作为主内容区的一部分存在，继续和聊天主任务区争抢空间。

用户已经给出明确方向：

- 删除中间的 `工作台 / 模型配置` 分页区。
- 将 `模型配置` 迁移到右上角，通过弹出悬浮窗打开。
- 左侧会话区域缩窄，并明确提示这里是会话栏。
- 主体改成两张独立卡片：左侧会话卡片，右侧聊天卡片。
- 释放聊天输入区和消息流空间，让工作台真正以对话为主。

## 目标

- 让 AI 页首屏直接进入“会话切换 + 聊天工作区”。
- 删除当前占用首屏空间的中间页签层。
- 将模型配置从主工作区移除，改为右上角按钮触发的悬浮窗。
- 让左侧会话区即使在空状态下也能明确表达其用途。
- 明显放大右侧聊天卡片的可用空间，尤其是输入区和消息流。

## 非目标

- 本轮不改后端接口、runtime stream、审批逻辑或 LLM 配置数据结构。
- 本轮不重做 `AgentModelConfigPane.vue` 的表单信息架构，只改变其承载方式。
- 本轮不新增复杂的会话筛选、搜索、标签系统。
- 本轮不引入新的全局弹窗框架，保持 AI 页面局部可控实现。

## 方案比较

### 方案 A：保留中间页签，只缩窄左栏

优点：

- 改动最小。

缺点：

- 根问题不解决，页签层仍然继续压缩聊天区。
- 模型配置仍是主区内容，和聊天工作区竞争主体位置。

### 方案 B：删除页签，模型配置改右侧抽屉

优点：

- 主区空间比当前更大。

缺点：

- 抽屉会横向挤压工作区。
- 打开配置时聊天主区容易变窄，违背“主体更突出”的目标。

### 方案 C：删除页签，模型配置改居中悬浮窗

优点：

- 彻底回收中间页签区域。
- 打开模型配置时不改变主体布局宽度。
- 更符合“配置是次级动作，聊天是主任务”的优先级。

缺点：

- 需要补一层页面内弹窗交互与遮罩。

## 设计结论

采用 `方案 C`：

- 页面移除 `WorkspaceTabs` 这一层。
- 顶部右侧提供 `模型配置` 按钮。
- 点击按钮后打开居中悬浮窗，内部复用现有 `AgentModelConfigPane.vue`。
- 主体区域固定为左右两张独立卡片：
  - 左卡片：会话栏
  - 右卡片：聊天工作区

## 顶层信息架构

### 页面头部

页面头部继续保留 `WorkspaceSummary`，但只承担两类职责：

- 左侧：页面标题 `AI 助手工作台`
- 右侧：轻量控制与状态

右侧控制收敛为：

- `模型配置` 按钮
- `LLM 状态` badge
- `低权限 / 高权限` 切换

删除：

- `工作台 / 模型配置` 中部页签

### 主体区

主体区只保留一层双列结构：

- 左列：会话卡片
- 右列：聊天工作台卡片

不再出现：

- 二级页签区
- 模型配置主内容区

## 会话卡片设计

对应组件：

- `frontend/src/components/agent/AgentSessionRail.vue`

### 结构

左侧会话区由“裸列表”改为有明确头部的独立卡片，内部结构为：

1. 卡片标题：`会话栏`
2. 副标题：`最近会话`
3. 会话列表或空状态

### 宽度

- 桌面端固定窄宽，目标范围 `200px - 220px`
- 不继续使用当前偏宽的侧栏比例

### 空状态

当没有历史会话时，显示简洁空状态：

- 主文案：`暂无历史会话`
- 辅助文案：`执行或追问后，会在这里沉淀会话记录`

### 列表项

保留现有最小信息模型：

- 标题
- 状态点
- 时间

明确不新增：

- 多行说明
- 冗长摘要
- 统计数字

## 聊天工作区卡片设计

对应组件：

- `frontend/src/components/agent/AgentWorkbench.vue`
- `frontend/src/components/agent/AgentWorkbenchTopbar.vue`
- `frontend/src/components/agent/AgentComposer.vue`

### 结构

右侧主卡片内部维持三层，但压缩外围留白：

1. 顶部薄状态条
2. 中部消息流
3. 底部输入卡

### 顶部状态条

只保留必要状态：

- 当前权限模式
- 当前会话状态
- 审批状态
- 实时进展文本

状态条保持“薄条”角色，不扩张成摘要面板。

### 消息流

- 占据主卡片的大部分高度
- 默认就是页面视觉焦点
- 不被额外的页签或介绍区挤压

### 输入卡

输入区需要明显放大：

- 文本输入框最小高度提高
- 外围 padding 收敛
- 快捷指令紧贴输入框下方排列
- 发送按钮保留整行主按钮样式

目标是让输入区看起来像“主操作区”，而不是现在偏瘦的附属块。

## 模型配置悬浮窗设计

建议新增组件：

- `frontend/src/components/agent/AgentModelConfigDialog.vue`

### 触发方式

- 由页面头部右上角的 `模型配置` 按钮触发

### 呈现方式

- 页面内居中悬浮窗
- 带半透明遮罩
- 打开时背景保留但降权

### 尺寸

- 桌面端宽度约 `720px`
- 高度不超过视口
- 内容区内部滚动

### 关闭方式

- 点击右上角关闭按钮
- 点击遮罩
- 按 `Esc`

### 内容承载

悬浮窗内部直接复用：

- `frontend/src/components/agent/AgentModelConfigPane.vue`

不复制表单逻辑，不分裂保存和测试能力。

## 交互约束

### 页面默认状态

- 默认直接进入聊天工作区
- 不需要切 tab

### 模型未就绪

- 头部仍显示 `LLM 状态` 警示
- 执行类请求不被 UI 阻塞
- 问答类请求依旧由现有逻辑决定是否提示

### 会话为空

- 左侧显示会话栏头部和空状态
- 右侧仍然允许立即开始对话或执行

### 悬浮窗打开时

- 不销毁聊天工作区
- 不改动工作区尺寸
- 只在视觉上降低背景优先级
