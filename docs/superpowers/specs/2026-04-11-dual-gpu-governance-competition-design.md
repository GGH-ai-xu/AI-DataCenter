# 双 GPU 并发竞争治理实验设计

**日期：** 2026-04-11

## 1. 目标

本实验用于补充作品书中“集群治理能力”的实证证据，核心目标不是重复证明“单张 GPU 可以限功率”，而是在同一台远端主机上构造双 GPU 并发负载场景，验证系统是否能够：

1. 在并发竞争环境中识别高功耗风险。
2. 只对目标 GPU 下发治理动作，而不影响同机另一张对照 GPU。
3. 在治理后让目标 GPU 的功耗、告警状态和波动幅度出现可观测回落。
4. 用同机对照方式把治理效果转化为评审可直接理解的图表证据。

## 2. 代码依据

本实验必须复用当前代码库已经存在的真实链路，而不是临时拼装无关脚本。涉及的关键实现如下：

- `testdoc/scripts/real_remote_budget_experiment.py`
  现有真实远端功耗治理实验脚本，已经能够通过 `SshLinuxProvider`、`AlertEngine`、`SchedulerEngine` 完成真实闭环。
- `testdoc/scripts/real_remote_budget_experiment_common.py`
  提供远端高负载脚本、采样参数、阈值和汇总逻辑。
- `backend/app/services/ssh_linux_provider.py`
  提供远端 GPU 采集、进程查询、功耗上限写入等能力。

因此，本实验的本质是：在现有单卡真实闭环的基础上，扩展为“双卡并发 + 单卡治理 + 单卡对照”的证据型实验。

## 3. 环境与前提

实验环境固定为用户提供的远端主机：

- 主机：`10.151.225.108`
- 账号：`dell`
- 端口：`22`
- GPU：`4 × RTX 3090`

实验开始前必须满足以下前提：

1. 至少存在 `2` 张空闲 GPU。
2. 两张候选 GPU 的空闲功耗均低于安全阈值，且利用率处于空闲水平。
3. 当前主机允许通过 `sudo` 执行 `nvidia-smi -pl`。

若任一前提不满足，实验立即停止并汇报，不允许静默降级成单卡实验。

## 4. 实验角色定义

在两张空闲 GPU 中定义两个角色：

- **治理 GPU**
  这张卡会在负载爬升后触发系统治理动作，是主要观测对象。
- **对照 GPU**
  这张卡运行相同负载，但不执行治理动作，用于形成同机同负载对照。

该角色划分的目的是让评审看到：在同一台机器、同一时间窗、相同负载条件下，系统治理动作只改变目标卡，而不会把现象混淆成“整机自然波动”。

## 5. 实验流程

### 5.1 GPU 选择阶段

1. 通过 `SshLinuxProvider.get_all_gpus()` 读取全部 GPU 实时状态。
2. 选出满足空闲条件的 GPU。
3. 从候选列表中选定两张卡，分别标记为治理 GPU 和对照 GPU。

### 5.2 基线采样阶段

1. 对两张卡同时采集基线窗口。
2. 记录两张卡的空闲功耗、空闲温度、空闲利用率和整机总功率。
3. 基线窗口用于证明实验开始前两张卡都处于可比状态。

### 5.3 并发负载阶段

1. 在两张卡上分别启动相同的高负载矩阵乘脚本。
2. 持续采样直到两张卡都进入高功耗区间。
3. 记录首次越阈时刻、峰值功耗和整机总功率。

### 5.4 治理动作阶段

1. 只对治理 GPU 触发系统治理动作。
2. 对照 GPU 保持原始功耗上限，不执行任何治理。
3. 治理动作仍通过现有系统链路完成，而不是直接绕开系统写 `nvidia-smi`。

### 5.5 治理后观测阶段

1. 持续采集治理后时间窗。
2. 对治理 GPU 与对照 GPU 同步记录功耗、温度、利用率、功耗上限和整机总功率。
3. 统计治理卡是否回落到阈值以下、对照卡是否仍维持高功耗、两者差异是否稳定存在。

## 6. 采集指标

### 6.1 单卡指标

对两张 GPU 都采集以下指标：

- `power_usage`
- `power_limit`
- `gpu_utilization`
- `temperature`
- `above_power_alert`

### 6.2 集群指标

- `total_power`
- 治理前后整机总功率变化
- 治理 GPU 在整机总功率中的占比

### 6.3 告警指标

- 首次越阈时刻
- 越阈样本数
- 治理后连续低于阈值的样本数
- 治理后窗口清洁率

### 6.4 时延指标

- 从首次越阈到治理动作下发的时间
- 从治理动作下发到目标 GPU 回落至阈值下方的时间
- 两张 GPU 功耗差开始稳定分离的时间

### 6.5 对照指标

- 治理 GPU 与对照 GPU 的峰值功耗差
- 治理后均值功耗差
- 治理后均值温度差
- 治理后波动幅度差

## 7. 成功判据

本实验成功必须同时满足以下条件：

1. 两张 GPU 均成功进入高负载状态。
2. 治理动作只作用于治理 GPU。
3. 治理 GPU 的功耗上限发生明确变化。
4. 治理后治理 GPU 的功耗曲线回落到阈值以下或显著低于治理前峰值。
5. 对照 GPU 在同一时间窗内仍维持未治理的高功耗特征。
6. 由此形成可视化差异，能够直接支持“系统具备针对性治理能力”的结论。

若只出现“整机一起降功率”或“双卡一起波动”，则实验不成立，因为无法证明是系统对目标对象的治理，而不是环境噪声。

## 9. 风险与约束

### 9.1 资源风险

若远端主机实际无法提供两张空闲卡，则不能执行本实验。

### 9.2 安全风险

不得对明显在使用中的 GPU 施加负载或功耗治理。

### 9.3 结果风险

若对照 GPU 自身功耗明显漂移，可能削弱对照效果；此时必须如实记录，而不是手工挑选数据掩盖波动。

## 10. 结论口径

若实验成功，本实验将支持如下口径：

“系统不仅能在单卡上执行功耗治理，还能在同机双 GPU 并发竞争场景中，对目标 GPU 实施有选择性的治理动作，并通过功耗、告警、时延和对照差异四个维度，证明治理动作真实改变了集群状态。”
