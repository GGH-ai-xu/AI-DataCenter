# 全站 UI 分舱重构设计

## 目标

在保留当前“纸感 / 水墨 / 印章”视觉语言的前提下，重构主要页面的信息组织方式，解决以下三个问题：

1. 组件大量平铺堆砌，缺少层次和主次。
2. 不同类别的信息混在同一长页面里，空间利用低且冗余。
3. 布局槽位不稳定，某个模块变高或位置变化时，会牵动不相关模块一起移动；部分表格和内容区还存在横向压缩、信息拥挤或视觉截断。

## 范围

本轮纳入主要页面：

- `frontend/src/views/Dashboard.vue`
- `frontend/src/views/TaskManager.vue`
- `frontend/src/views/Scheduler.vue`
- `frontend/src/views/EnergyOptimization.vue`
- `frontend/src/views/MonitorCenter.vue`
- `frontend/src/views/AIAssistant.vue`
- `frontend/src/views/AlertCenter.vue`

次要页面如 `GpuDetail.vue` 保持轻量整理，不作为结构重构主战场。

## 非目标

- 不修改导航路由语义。
- 不新增后端接口。
- 不改产品功能，只重构前端页面结构、组件边界与视觉层级。
- 不放弃当前东方纸墨视觉风格。

## 现状问题

### 1. 页面平铺过长

`Dashboard.vue`、`TaskManager.vue`、`Scheduler.vue`、`EnergyOptimization.vue`、`AIAssistant.vue` 都是超大单文件，并且把摘要、控制、图表、说明、日志、表格堆在一个页面流里。用户进入页面后很难快速理解“当前该看什么、该先做什么”。

### 2. 控制区与结果区混排

例如：

- `Scheduler.vue` 同时平铺预算治理、碳预算、调度器状态、手动功耗控制、调度结果、策略对比、评估、报告。
- `TaskManager.vue` 将统计、公平分析、规则配置、处置表格并列堆叠。
- `AIAssistant.vue` 把 AI 执行控制、聊天解释、LLM 配置放在一页内直接竞争注意力。

这会让“操作”与“观察”互相干扰。

### 3. 布局耦合与稳定性差

当前大量页面使用简单网格把不相关模块放在同一排里。某个卡片内容增长时，会把同排其他卡片整体向下推。页面内还存在表格与长说明混在一起的情况，导致局部变动影响整页布局。

## 设计原则

### 1. 统一三层结构

每个主要页面统一为：

- 第一层：指挥摘要
- 第二层：任务分舱 Tab
- 第三层：稳定槽位内容区

### 2. Tab 按用户任务分，不按技术组件分

Tab 的目标不是“把组件藏起来”，而是按用户的工作意图拆分：

- 看判断
- 做操作
- 看结果
- 做复盘

### 3. 稳定槽位优先于自由流式堆叠

Tab 内容区使用固定职责的左右槽位或上下槽位：

- 左槽位：表单、规则、任务、动作入口
- 右槽位：图表、结果、说明、审计、解释

不同槽位内部独立纵向流动，槽位之间不互相挤压。

### 4. 组件边界清晰

超大页面拆分为多个子组件。页面文件只保留：

- 状态组合
- Tab 切换
- 数据加载编排

具体面板、摘要卡片、规则区、结果区、表格区独立成子组件，避免继续在单文件内耦合。

## 全站结构方案

### Dashboard

改为：

- `概览`
- `接入与自检`
- `实时态势`

其中：

- `概览` 只保留治理判断、当前风险、关键状态、快捷入口。
- `接入与自检` 集中承载接入中心、平台自检、桌面服务、远端协助。
- `实时态势` 承载 GPU 状态、功耗趋势、利用率分布、近期告警。

### TaskManager

改为：

- `待处置任务`
- `公平治理`
- `规则配置`

其中：

- `待处置任务` 放任务筛选、风险确认、处置表格。
- `公平治理` 放公平指数、用户占用结构、让路候选。
- `规则配置` 独立承载用户治理规则编辑，不再与任务表格混排。

### Scheduler

改为：

- `治理控制`
- `执行结果`
- `审计与报告`

其中：

- `治理控制` 放预算、碳预算、自动调度、手动功耗控制。
- `执行结果` 放调度结果、策略对比、AI 评估。
- `审计与报告` 放报告与审计日志。

### EnergyOptimization

改为：

- `总览`
- `预测与对比`
- `AI 洞察`

其中：

- `总览` 展示核心指标和当前判断。
- `预测与对比` 放趋势、预测、历史对比。
- `AI 洞察` 放异常、解释、优化建议。

### MonitorCenter

保留已有 Tab 思路，但重做每个 Tab 内的槽位稳定性，避免不同卡片因为内容高低互相干扰。

### AIAssistant

改为：

- `执行控制`
- `对话解释`
- `模型配置`

其中：

- `执行控制` 作为首要任务区，优先展示可审核、可演练、可执行动作。
- `对话解释` 单独承载问答。
- `模型配置` 独立放置，不再和操作区抢注意力。

### AlertCenter

保留单页，但增加摘要层与筛选层，表格独立占据稳定主槽位，避免头部说明和表格互相压缩。

## 组件拆分方案

按页面建立局部组件目录，例如：

- `frontend/src/components/dashboard/*`
- `frontend/src/components/scheduler/*`
- `frontend/src/components/tasks/*`
- `frontend/src/components/energy/*`
- `frontend/src/components/ai/*`

优先抽离：

- 页面摘要头部
- Tab 导航条
- 左右稳定槽位容器
- 表格面板
- 图表面板
- 规则/表单面板
- 审计/说明面板

## 布局与稳定性规则

### 1. 不让不相关模块共用弹性高度

不再把互不相关的卡片直接放进同一自动行高网格里。改用“左列堆栈 + 右列堆栈”或“上区摘要 + 下区内容”的稳定布局。

### 2. 表格和长列表独立滚动

任务表、告警表、时间线表等需要使用独立滚动容器，避免整页被表格拉长，也避免横向被压缩后发生视觉截断。

### 3. 卡片内部允许内容自然伸展

避免用硬编码高度把内容裁掉。需要固定高度时，只对滚动容器固定，不对文本内容区强裁切。

### 4. 移动端和窄宽度降级规则明确

桌面端使用双槽位；中等宽度下折叠为上下槽位；窄屏时 Tab 仍保留，但内容改为单列流。

## 视觉保持与升级范围

保持：

- 宣纸背景
- 朱印、墨色、青绿体系
- 现有标题语气和东方化装饰

升级：

- 页首摘要更克制，减少一次性大段堆叠
- 卡片层级更明确
- Tab 作为分舱主结构而不是附属控件
- 通过留白、分段和信息节奏提升“设计感”

## 验证标准

重构完成后需要满足：

1. 用户进入每个主要页面后，首屏只需要理解“状态 + 主动作 + 入口”，不会被十几个模块同时轰炸。
2. 主要页面都能指出明确的任务分舱 Tab。
3. 调整某个面板内容高度时，不会让无关面板随之错位。
4. 表格、图表、说明区不再互相挤压，也不出现明显内容截断。
5. 路由、功能和现有数据流保持兼容。
