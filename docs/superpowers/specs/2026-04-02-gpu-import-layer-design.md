# GPU 导入层与控制台边界重构设计

## 背景

当前首页 `Dashboard` 同时承担接入中心、自检入口和控制台首页三种职责，导致入口与治理边界混杂。用户希望在进入管理页前先完成一次明确的“设备导入”流程：先选择本地或远程来源，扫描 CPU 与 GPU 当前状态，勾选要纳入治理的计算卡，导入后再进入控制台。进入控制台后，系统只显示和治理本次导入的卡，不再暴露连接切换逻辑。

## 目标

- 新增独立导入层，作为进入控制台前的唯一入口。
- 导入层负责本地/远程选择、远程地址输入、设备扫描、GPU 多选、导入提交。
- 控制台只消费“当前导入上下文”，不再承担接入切换职责。
- 所有展示、分析、治理接口都只围绕已导入 GPU 生效。
- 应用启动时，如果存在有效导入上下文，则直接进入控制台；否则进入导入层。

## 非目标

- 不保留控制台内的本地/远程切换器。
- 不支持同时维护多套并行导入上下文。
- 不做“只在前端隐藏未导入 GPU”的表层筛选；后端必须强约束。

## 推荐方案

采用“独立导入页”方案，新增路由 `/import`。导入层负责接入与选卡，控制台负责治理。相比继续复用首页向导化或做路由拦截弹层，这种拆分的职责边界最清晰，最符合“控制台只负责管理导入卡”的要求。

## 信息架构

### 启动判定

应用启动先读取当前导入上下文：

- 若存在且有效，直接跳转控制台默认页。
- 若不存在或失效，跳转 `/import`。

### 导入层

`/import` 页面承担以下步骤：

1. 选择来源模式：本地或远程。
2. 远程模式下输入 Agent 地址并测试连通性。
3. 扫描目标机器，获取 CPU 摘要、内存摘要、GPU 列表和每张卡的当前状态。
4. 勾选一个或多个 GPU。
5. 点击“导入并进入控制台”。

### 控制台层

控制台包含现有总览、任务、调度、告警、观察、能耗、AI 等页面，但这些页面只面向当前导入 GPU 工作：

- 未导入 GPU 不显示。
- 未导入 GPU 不参与分析。
- 未导入 GPU 不允许治理动作。

控制台只保留一个明确入口用于“重新导入管理卡”，该入口跳回 `/import`。

## 导入上下文模型

后端新增 `ImportContextService`，保存单个“当前导入上下文”，字段建议如下：

- `source_mode`: `local` 或 `remote`
- `agent_url`: 本次导入使用的 Agent 地址
- `agent_label`: 可选展示名
- `imported_gpu_indexes`: 导入的 GPU 索引数组
- `imported_at`: 导入时间
- `snapshot`: 导入时的设备摘要
- `valid`: 当前上下文是否有效
- `invalid_reason`: 失效原因，可选

`snapshot` 至少包含：

- CPU 型号、核心数、总内存、当前 CPU 利用率
- 每张 GPU 的索引、名称、温度、功耗、利用率、显存使用、时间戳

系统只维护一份当前导入上下文，不为不同远程地址保留多套历史导入集合。用户需要切换来源或远程主机时，必须通过“重新导入”重新建立上下文。

## 后端接口设计

### 1. 扫描候选设备

新增候选扫描接口，输入来源模式和远程地址，返回：

- 规范化后的目标地址
- Agent 健康状态
- CPU 与系统摘要
- 全部 GPU 当前状态

该接口只做探测，不保存导入结果。

### 2. 提交导入

新增导入提交接口，输入：

- 来源模式
- 目标地址
- 展示名
- 勾选的 GPU 索引数组

后端需要先重新扫描一次，确认这些索引当前存在，再保存导入上下文，并把运行时治理范围切换到该集合。

### 3. 读取当前导入上下文

新增读取当前导入上下文接口，用于前端启动判定和控制台顶部状态展示。

### 4. 清空导入

新增清空或重置导入接口，用于“重新导入管理卡”。调用后当前控制台状态失效，前端回到 `/import`。

## 后端过滤与安全边界

过滤必须在后端统一执行，不允许只在前端做展示裁剪。

### 统一过滤范围

`ImportContextService` 提供统一方法：

- 过滤 GPU 列表
- 过滤进程列表
- 过滤派生分析输入
- 校验治理目标是否越界

### 接口级约束

- GPU 列表、历史、调度状态、能耗统计、观察回放等接口，只返回导入 GPU 范围内的数据。
- 任务列表只返回运行在导入 GPU 上的进程。
- 告警、公平性分析、治理建议、能耗分析等派生接口，必须以过滤后的数据重新计算。
- `set_power_limit`、暂停/恢复/终止任务、调度执行等接口，必须在后端再次校验目标 GPU 或进程是否属于导入范围；不属于则拒绝执行。

## 上下文失效规则

满足以下任一情况时，当前导入上下文标记为失效：

- Agent 不可达
- 导入的 GPU 索引在当前扫描结果中不存在
- 扫描结果为空，无法确认导入对象

失效后：

- 后端在导入上下文中写入 `valid = false`
- 控制台相关接口返回“需要重新导入”的状态
- 前端统一跳转 `/import`

## 前端改造要点

### 路由

- 新增 `/import`
- 现有控制台首页继续保留 `/`
- 启动阶段根据导入上下文在两者之间跳转

### 页面拆分

- 从 `Dashboard.vue` 中迁移接入中心相关逻辑到新的导入页
- `Dashboard.vue` 收敛为纯控制台首页
- `App.vue` 的放行条件从“Agent 已接通”调整为“存在有效导入上下文”

### 导入页展示

导入页至少展示：

- 来源模式
- 远程地址输入与测试反馈
- CPU 摘要
- 全部 GPU 列表
- 每张 GPU 的实时状态
- 多选导入区
- 导入按钮

### 控制台状态提示

控制台保留只读状态摘要，例如：

- 当前导入来源：本地或远程
- 当前目标地址
- 当前纳入治理的 GPU 索引集合
- 重新导入按钮

但不再内嵌接入配置表单。

## 兼容与迁移

- 现有 `/api/system/connection` 相关接口在导入层改造完成前仍可保留，作为过渡能力。
- 完成迁移后，控制台页面不再依赖连接配置接口驱动主流程。
- 旧的 `workspaceReady` 语义需要替换，避免“Agent 在线但未导入 GPU 时误判为可进入控制台”。

## 验证策略

### 后端测试

- 导入上下文持久化与加载
- 扫描接口返回结构
- 导入提交的索引校验
- GPU/进程过滤逻辑
- 越界治理动作拒绝
- 上下文失效判定

### 前端测试

- 无导入上下文时跳转 `/import`
- 有有效导入上下文时直达控制台
- 导入成功后跳转控制台
- 重新导入后控制台范围更新

### 集成测试

- 本地导入一组 GPU 后，控制台只展示该集合
- 切换为远程重新导入后，旧范围不再可见
- 远程目标离线后，系统回退到导入层

## 风险与控制

- 风险：仅前端筛选会导致后端仍能越界治理。
  控制：所有治理接口必须走导入上下文校验。
- 风险：导入成功后运行时范围未同步，前后端视图不一致。
  控制：提交导入时同步刷新 Agent 目标与导入上下文，再返回成功。
- 风险：旧首页逻辑残留，控制台继续暴露连接切换入口。
  控制：将接入中心能力整体迁出 `Dashboard.vue`，只保留“重新导入”入口。
