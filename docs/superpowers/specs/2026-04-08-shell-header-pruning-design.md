# 双头部页面壳层大卡裁剪设计

## 背景

当前控制台采用两层头部结构：

- 壳层统一头部：由 `frontend/src/views/ConsoleShell.vue` 渲染，负责展示工作区类型、当前页面名称、连接状态和三项摘要指标。
- 页面内头部：由各页面自己渲染，例如总览页的 `dashboard-summary`、观察页的 `WorkspaceSummary(title="系统观察")`、治理页的 `WorkspaceSummary + quickStats`。

这套结构在部分页面上会形成明显重复：

- 第一层已经说明“当前在什么工作区、状态如何”
- 第二层又再次说明“当前页面是什么、状态如何”

结果是首屏出现两张连续的大卡，信息职责重叠，页面纵向空间被吃掉，视觉重点也被冲淡。

## 目标

只对已经存在“第二层完整标题/摘要”的页面裁掉壳层统一大卡，让页面首屏只保留真正和内容绑定的那一层摘要。

本次改动只调整前端布局表达，不改数据来源，不改交互能力，不改现有 banner、侧栏、移动端导航和页面主体结构。

## 范围

本次裁剪只覆盖以下页面：

- `/`
- `/monitor`
- `/governance/actions`
- `/governance/policies`
- `/governance/review`

这些页面共同特征是：页面内部已经自带完整标题、状态摘要或 quick stats，不需要壳层再重复提供一层大标题卡。

本次不处理以下页面：

- `/energy`
- `/alerts`
- `/ai`

原因不是这些页面永远保留壳层大卡，而是它们当前不满足“已经有第二层完整标题摘要”的判断，不应和这次一起裁。

## 设计结论

### 1. 用路由级声明控制壳层头部显隐

不在各页面里各自删除逻辑，而是在路由元信息上声明哪些页面隐藏壳层大卡。

推荐做法：

- 在路由定义中为目标页面添加类似 `meta.hideShellHeader = true` 的标记
- `ConsoleShell.vue` 只根据当前路由 meta 决定是否渲染 `app-chrome`

这样页面是否显示壳层大卡成为路由级能力，而不是散落在各页面里的条件分支。

### 2. 被隐藏的仅是壳层大卡，不是壳层能力

当页面命中隐藏规则时，仅移除 `ConsoleShell.vue` 中这一整块大卡：

- 工作区 eyebrow
- 页面大标题
- 连接状态 pill
- 页面描述
- 三项摘要指标

以下壳层能力必须继续保留：

- 左侧主导航
- 顶部运行时 banner
- 更新通知 banner
- 移动端导航
- 主体 `router-view`
- 页面切换动画

也就是说，这次不是“页面脱离壳层”，只是“页面不再重复显示壳层摘要头”。

### 3. 页面内头部继续作为唯一首屏摘要

被裁页面需要保留它们现有的页面内摘要：

- 总览页继续保留 `dashboard-summary`
- 观察页继续保留 `WorkspaceSummary(title="系统观察")`
- 治理页继续保留 `GovernanceLayout` 中的 `WorkspaceSummary + quickStats`

裁剪后的预期是：

- 用户进入这些页面时，首屏只看到一层标题摘要
- 这层摘要直接绑定当前页内容，而不是泛化的工作区描述

## 交互与视觉规则

### 1. 不做“隐藏后补一个迷你标题条”

本次不把壳层大卡替换成迷你 breadcrumb 或压缩条。

原因是这些页面已经有自己的标题摘要，再补一层弱化头部仍然会保留重复感，只是变轻，不会真正变干净。

### 2. 只对命中路由生效

隐藏规则必须是显式白名单，而不是“凡是页面里出现 `WorkspaceSummary` 就自动隐藏”。

原因是：

- 总览页不是用 `WorkspaceSummary`
- 后续别的页面即使引入同名组件，也不一定表示存在双头部问题

因此判断标准应基于产品意图，而不是模板字符串猜测。

### 3. 页面间保持一致

一旦某个工作流页面已经采用“页面内头部承担首屏摘要”，同组页面要保持一致。

因此治理页三个子路由要一起处理，而不是只裁其中一个。

## 测试与回归要求

本次需要新增或调整结构测试，覆盖以下断言：

- 路由中明确标记哪些页面隐藏壳层大卡
- `ConsoleShell.vue` 依据路由 meta 控制 `app-chrome` 显隐
- 总览、观察、治理仍保留页面内自己的标题摘要
- `energy / alerts / ai` 路由本次不带隐藏标记

不需要新增端到端视觉测试，也不需要改后端测试。

## 非目标

以下内容不属于本次设计：

- 重做观察页、总览页、治理页自己的摘要内容
- 合并页面内二级摘要卡
- 修改 banner 样式
- 调整侧栏信息结构
- 处理能耗、告警、智能页是否也要裁壳层大卡

本次只解决“已经有页面内摘要时，壳层再来一层大卡”的冗余问题。
